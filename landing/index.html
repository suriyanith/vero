Vero

An evidence-first medical coding assistant. Every suggested ICD-10 code comes with the exact sentence that supports it — verified in code, reviewed by a human, and recorded in an append-only audit trail.

View the code on GitHub

This page is a static replay of precomputed results. No backend, no AI calls, no text input.

The problem

Doctors document visits in free text; insurers pay on standardized codes; medical coders translate between them. Errors cost money in both directions: under-coding leaves documented conditions unpaid, while over-coding creates compliance risk — CMS RADV audits claw back payments for diagnoses the chart doesn't support, and regulators have specifically flagged AI tools that push coders to add diagnoses. Every code needs to be traceable to evidence, verified quickly, and defensible later.

How Vero works

  1. Extract. An LLM reads the note and lists every condition with verbatim quotes, a status (active, historical, rule-out, negated…), and MEAT evidence tags.
  2. Verify. Python checks every quote against the note character-by-character. A quote that isn't really there is dropped — the AI cannot invent evidence.
  3. Retrieve. Candidate codes come from the real FY2027 ICD-10-CM code set via Postgres full-text + trigram search, with category expansion.
  4. Select. The LLM chooses only from those retrieved real codes; anything outside the list is discarded. Tabular conventions (Excludes1, "use additional code") ride along.
  5. Finalize. Deterministic rules validate billability, reconcile conflicts, map each code to its CMS-HCC V28 category, and assign a readable confidence level. A human accepts, rejects, or modifies every code.

    What makes it defensible
    
      
      
        
    • Mechanically verified evidence. 0 unverified quotes shown to users — enforced by code and tests, not policy.
      • 
        
    • Codes only from the official code set. 98,403 FY2027 codes loaded from CMS files; only billable codes can surface.
      • 
        
    • Two-way review. Audit mode flags unsupported codes to remove and documented HCCs that were never submitted.
      • 
        
    • An append-only audit trail. Every decision stores who, when, what changed, and a snapshot of the evidence the reviewer saw. Edits and deletes are impossible.
      • 
        
    • Readable confidence. Rule-based High/Medium/Low with every reason recorded, checked against live acceptance rates and the evaluation set.
      • 
      
    
    
    

    
    
      
    Tech
    
      
    
        Django 6 + Django Ninja + PostgreSQL 16 · a framework-free Python pipeline (Pydantic) with
        exactly two Gemini calls per note · React + TypeScript + Vite + Tailwind · database-backed
        task queue (no Redis) · TypeScript API types generated from the OpenAPI schema ·
        220+ automated tests, CI with lint/typecheck/secret-scanning.
      
    
    
    

    
    
      
    Why it runs locally
    
      
    
        A public site that calls an AI API on every request exposes quota and cost to anyone, and
        an open text box invites someone to paste a real patient's note — which would mean handling
        PHI and HIPAA obligations. Vero therefore runs locally on synthetic notes only, with a PHI
        tripwire that rejects anything resembling real identifiers. This demo page is static.
